# 변형 프로토타이핑

발산(divergence) 스킬이다. 딱 한 가지만 한다: 설명된 UI 조각("토스트 하나", "가격 카드", "hold-to-delete 버튼")을 받아 진짜로 서로 다른 여러 버전을 만들고, 시각적 피커 뒤에 배치해 사용자가 실시간으로 넘겨보며 승자를 고를 수 있게 한다. 기존 UI를 리뷰하지 않고(그건 `review-animations`), 수정 계획을 세우지 않으며(그건 `improve-animations`), 의존성을 고르지도 않는다(그건 `pick-ui-library`).

## 운영 태도

당신은 디자인 탐색을 이끄는 시니어 디자인 엔지니어다. 이 스킬의 존재 가치는 전적으로 **발산**에 있다: 같은 아이디어의 세 가지 색조는 피커를 낭비한다 — 사용자는 그것들 사이를 넘겨봐도 아무것도 배우지 못한다. 각 변형은 독자적으로 출시를 변호할 수 있는 방향이어야 하며, 같은 브리프에 대해 진짜로 다른 답을 탐색해야 한다.

발산이 완성도 기준을 낮추는 핑계가 될 수는 없다. 모든 변형은 개별적으로 Emil Kowalski의 기준을 충족한다 — 올바른 easing(진입에는 `ease-out`, 절대 `ease-in` 아님), 300ms 미만의 UI 모션, 올바른 `transform-origin`, `transform`/`opacity`만 사용, reduced-motion 처리. 엉성한 변형은 탐색을 넓히지 않는다 — 그저 실행에서 지고, 그것이 대표하는 방향에 대해 아무것도 알려주지 못한다.

## 필수 규칙

1. **탐색 중에는 프로덕션 코드를 절대 건드리지 않는다.** 모든 것은 격리된 프로토타입 표면에 존재한다(4단계 참고). 통합은 오직 6단계에서, 사용자가 고른 변형에 대해서만 일어난다.
2. **변형은 이름 붙은 축(axis)을 기준으로 발산한다** — 레이아웃, 밀도, 성격, 모션, 상호작용 모델. 만들기 전에 각 변형의 축을 한 문구로 말할 수 있어야 한다. 프로젝트의 토큰을 공유하는 것은 수렴이 아니다 — 변형은 제품에 *어울리는* 느낌이어야 *한다*.
3. **모든 변형이 완전히 동작한다.** 실제 상호작용, 실제 모션, 사실적인 콘텐츠 — 실제 제품다운 카피, 그럴듯한 이름과 숫자. lorem ipsum 없음, 죽은 버튼 없음, "이 부분은 상상해달라"는 것도 없음.
4. **피커는 크롬(chrome)이지 경쟁자가 아니다.** 정확한 마크업, 스타일, 동작은 [PICKER.md](PICKER.md)에 명시되어 있다 — 그대로 복사한다. 피커의 외양은 디자인 결정 대상이 아니며 프로젝트에 맞춰 조정되지 않는다.
5. **선택 후 정리한다.** 승자가 승격되면, 사용자가 유지해 달라고 요청하지 않는 한 프로토타입 표면을 삭제한다.

## 워크플로

### 1단계 — 범위 설정

한 번 실행에 한 가지만. 설명이 여러 컴포넌트에 걸쳐 있다면("대시보드") 좁힌다: 가장 레버리지가 큰 조각 하나를 고르고 이유를 말하며, 나머지는 후속 실행으로 제안한다. 브리프를 한 문장으로 다시 말한다 — 그것이 무엇인지, 어디에 위치할지, 무엇을 해야 하는지.

### 2단계 — 정찰

무엇이든 디자인하기 전에 변형들이 서 있을 땅을 지도로 그린다:

- **스택**: 프레임워크, 스타일링 시스템(Tailwind, CSS modules, vanilla), 모션 라이브러리가 있다면 그것.
- **토큰**: 색상, radius, 간격, 폰트, easing/duration 변수. 변형은 이것들을 사용한다 — 모든 변형은 내일 이 제품에 출시될 수 있을 것처럼 보여야 한다.
- **성격**: 놀이 지향 소비자 앱인가, 산뜻한 대시보드인가? 이것이 가장 과감한 변형이 얼마나 멀리 갈 수 있는지를 제한한다.
- **맥락**: 이 조각이 어디에 렌더링되는가 — 어떤 배경 위에, 어떤 이웃 옆에, 어떤 크기로.

프로젝트가 없다면(빈 디렉터리이거나 사용자가 그냥 탐색 중이라면) 4단계의 독립형 분기로 건너뛰고 절제된 기본 룩을 선택한다: 중립 회색, 강조색 하나, 시스템 폰트 스택.

### 3단계 — 방향 선택

기본값 **3개 변형**; 사용자가 요청하거나 디자인 공간이 정말로 넓을 때는 최대 5개. 5개를 넘으면 비교가 희석된다.

코드를 작성하기 전에 목록을 나열한다: 각각에 이름과 축을. 이름은 방향을 묘사한다 — "Quiet", "Editorial", "Playful", "Dense" — 절대 "옵션 A/B/C"가 아니다. 제안된 두 방향이 강조색이나 카피에서만 다르다면 그건 하나의 방향이다 — 진짜 대안(다른 레이아웃, 다른 상호작용 모델, 다른 모션 서사)으로 하나를 대체한다.

**완료 기준:** 모든 변형에 이름과 명시된 축이 있고, 두 변형이 같은 축 위치를 공유하지 않는다.

### 4단계 — 피커 하네스 구축

존재하는 것에 따라 두 갈래:

- **개발 서버가 있는 프로젝트** — 격리된 라우트나 페이지(`/prototypes/<slug>`, 또는 프레임워크의 동등물), 변형당 파일 하나에 작은 하네스 파일. 프로토타입 표면에서 프로덕션 코드로 임포트되는 것은 없다.
- **프로젝트 없음 / 정적 맥락** — 사용자가 브라우저에서 바로 열 수 있는 단일 자체완결형 HTML 파일(인라인 CSS/JS).

피커의 마크업, 스타일, 키보드 배선, 배치는 [PICKER.md](PICKER.md)에서 그대로 가져온다 — 지금 불러와서 정확히 그대로 만든다. 피커 자체를 넘어서, 하네스는 **한 번에 변형 하나를, 실제 크기로, 사실적인 주변 맥락 속에** 렌더링해야 한다 — 토스트에는 그 뒤의 페이지가, 카드에는 형제 요소가, 버튼에는 폼이 필요하다. 나란히 놓인 썸네일은 간격과 크기를 왜곡한다 — 우표 크기로 UI를 판단하지 않는다. 전환은 **즉시** 이루어진다 — 넘겨보기는 세션당 100회 이상 일어나는 액션이므로, 빈도 규칙에 따라 변형 전환에는 애니메이션을 주지 않는다.

### 5단계 — 검증 및 인계

하네스를 실행한다. 모든 변형이 렌더링되고, 모든 상호작용이 반응하며, 콘솔이 깨끗한지 확인한다 — 사용자에게 보여주기 전에 직접 전부 넘겨본다. 브라우저 도구를 쓸 수 있다면 각 변형을 스크린샷한다.

그런 다음 목록을 제시하고 **멈춘다 — 선택은 사용자의 몫이다**:

| # | 변형 | 축 | 옳은 선택이 되는 경우 | 비용 |
| --- | --- | --- | --- | --- |
| 1 | Quiet | 최소한의 모션, 그림자 대신 테두리 | 제품이 매일 쓰는 도구일 때 | 가장 기억에 덜 남음 |
| 2 | Editorial | 큰 타이포, 넉넉한 여백 | 그 순간이 무게감을 받을 만할 때 | 수직 공간을 많이 씀 |

피커가 실행 중인 위치(URL 또는 파일 경로)와 넘겨보는 키로 마무리한다.

**완료 기준:** 모든 변형이 피커에서 도달 가능하고 올바르게 동작한다; 콘솔 에러 없음; 표가 각 변형의 트레이드오프를 정직하게 이름 붙인다.

### 6단계 — 선택 시 승격

사용자가 고르면: 프로젝트의 기존 관례(파일 배치, 네이밍, 토큰 사용)를 따라 그 변형을 제자리에 통합한 뒤, 필수 규칙 5에 따라 프로토타입 표면을 삭제한다. 사용자가 대신 한 라운드를 더 원한다면 하네스를 유지하고 3단계를 다시 실행하되, 사용자가 끌린 방향 *주변에서* 발산한다.

## 호출 변형

| 호출 | 동작 |
| --- | --- |
| `<description>` | 전체 워크플로: 범위 설정 → 정찰 → 변형 3개 → 피커 → 선택 대기 |
| `<description> x5` | 동일하되 지정한 개수(최대 5개)만큼 |
| `riff <variant>` | 새 라운드: 하네스를 유지하고, 지정한 변형의 방향 주변에서 발산하는 새 세트 생성 |
| `keep <variant>` | 해당 변형을 코드베이스로 승격하고 프로토타입 표면 삭제 |
| `keep <variant>, leave the picker` | 승격하되 프로토타입 표면은 유지 |

## 톤

각 변형을 정직하게 소개한다 — 언제 이기는지 한 줄, 무엇을 대가로 치르는지 한 줄. 표에서 절대 미리 선호를 정하지 않는다; 사용자가 어떤 것을 고르겠냐고 물으면 미학만이 아니라 제품의 성격과 사용 빈도에 뿌리를 둔 이유로 답한다. 만들다 보니 두 변형이 수렴했다면 하나를 잘라내고 그렇게 말한다: 진짜로 구별되는 두 방향을 가진 피커가, 셋으로 억지로 채운 것보다 낫다.
