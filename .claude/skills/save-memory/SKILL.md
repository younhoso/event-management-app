대화 범위: $ARGUMENTS

`$ARGUMENTS`가 있으면 그 주제와 관련된 대화 구간에 집중한다. 비어 있으면 이번 세션에서 아직 메모리로 남기지 않은 전체 대화를 검토 대상으로 삼는다.

이 스킬은 시스템 프롬프트에 이미 정의된 auto memory 시스템(타입: user/feedback/project/reference, 프론트매터 포맷, 저장 금지 목록)을 그대로 따른다. 아래는 그 규칙을 이번 실행에서 놓치지 않도록 강제하는 절차다.

## 1단계 — 후보 추출

대상 대화 구간을 다시 훑으며 다음 4가지 렌즈로 각각 후보를 뽑는다. 없으면 억지로 만들지 않는다.

- **user**: 사용자의 역할·전문성·현재 관심사에 대해 새로 알게 된 것
- **feedback**: 사용자가 명시적으로 교정했거나("아니 그거 말고"), 놀라운 접근을 별다른 반박 없이 승인한 것("어, 그거 맞아" 같은 조용한 확인 포함)
- **project**: 누가/무엇을/왜/언제 했는지 — 코드나 git log만으로는 알 수 없는 배경·동기·기한
- **reference**: "그건 Linear/Slack/Notion 어디에 있어" 같은 외부 시스템 위치 정보

각 후보에 대해 "저장하면 안 되는 것" 필터를 통과시킨다: 코드를 읽으면 바로 알 수 있는 패턴/구조/경로, git log로 알 수 있는 이력, 이미 CLAUDE.md에 있는 내용, 이번 대화에서만 의미 있는 휘발성 작업 상태는 전부 제외한다. 사용자가 활동 요약이나 목록 저장을 요청한 경우, 그 자체를 저장하지 말고 "그중 무엇이 뜻밖이었는지"를 스스로에게 물어 그 답만 남긴다.

## 2단계 — 기존 메모리와 대조 (건너뛰지 말 것)

새 메모리를 추가만 하고 끝내지 않는다. 반드시:

1. 해당 프로젝트의 `MEMORY.md`를 읽는다.
2. 이번에 저장하려는 내용과 주제가 겹치거나 모순될 수 있는 기존 메모리 파일을 찾아 Read한다(파일명·description으로 추정, 애매하면 grep).
3. 기존 파일이 이번 대화 내용으로 인해 **틀리게 되거나 낡게 되었다면**, 새 메모리를 쌓기만 하지 말고 그 기존 파일도 함께 정정한다. 예: 아키텍처를 바꾸는 변경이 있었다면 그 아키텍처를 전제로 쓰인 옛 메모리의 해당 문장을 취소선/정정 표시하고 새 메모리로 링크한다.
4. 코드베이스에 체크인된 문서(CLAUDE.md, `.claude/memory/*.md` 등)가 이번 변경으로 stale해졌다면, 메모리 파일 안에 "⚠️ 후속 조치 필요" 형태로 남겨 다음 세션에서 갱신을 제안할 수 있게 한다. 체크인 문서 자체를 이 스킬이 직접 고치지는 않는다.

## 3단계 — 저장

각 후보를 `{type}_{slug}.md` 파일로 저장한다. frontmatter:

```markdown
---
name: { short-kebab-case-slug }
description: { 한 줄 요약, 관련성 판단용이므로 구체적으로 }
metadata:
  type: { user|feedback|project|reference }
---
```

본문 규칙:

- feedback/project 타입은 "규칙/사실" → **Why:** (사용자가 준 이유, 과거 사건, 제약) → **How to apply:** (언제 적용할지) 순서로 쓴다.
- 관련 메모리는 `[[다른-메모리-name]]`으로 링크한다. 아직 없는 이름을 링크해도 된다 — 나중에 쓸 가치가 있다는 표시다.
- 상대 날짜("어제", "다음 주 목요일")는 절대 날짜로 변환해서 쓴다.

마지막으로 `MEMORY.md`에 한 줄씩 추가/수정한다: `- [제목](파일명.md) — 핵심 훅 한 줄`. 200줄 넘지 않게 간결히 유지하고, 이번에 정정한 기존 항목의 훅 문구도 필요하면 같이 갱신한다.

## 4단계 — 보고

사용자에게 다음을 간결히 보고한다:

- 새로 저장한 메모리 (파일명 + 한 줄 요약)
- 기존 메모리 중 정정한 것이 있다면 무엇을 왜 고쳤는지
- 저장하지 않기로 판단한 후보가 있다면(예: 이미 CLAUDE.md에 있어서 제외) 짧게 언급

후보가 하나도 없으면 억지로 만들지 말고 "이번 대화에서 새로 저장할 만큼 놀랍거나 결정적인 내용은 없었습니다"라고 말한다.
