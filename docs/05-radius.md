# 05. Radius — 모서리

## 채우는 칸

방식 1 — 자리마다 직접 지정
```
## Radius
- 버튼 [__]px
- 카드 [__]px
- 입력창 [__]px
- 원형은 999
```

방식 2 — 기준값 하나에서 파생 (값이 늘어나지 않아 권장)
```
## Radius
- 기준값 [__]px
- 작은 요소(배지, 체크박스) 기준값 - [__]px
- 버튼·입력창 기준값 - [__]px
- 카드·다이얼로그 기준값
- 큰 컨테이너·모달 기준값 + [__]px
- 원형은 999
```

## 작성 규칙

- **0도 완성된 선택.** 전부 각지게 가는 것은 덜 다듬어진 게 아니라 "업무 도구는 단단해 보여야 한다"는 의도적 선택이 될 수 있음 (IBM이 이 방식)
- **애매한 값보다 0 또는 뚜렷한 값이 낫다.** 어중간하게 둥근 값은 "그냥 둥글게 해봤나?" 싶은 인상을 줌
- **원형은 반드시 `999`로 고정.** 크기의 절반을 계산해서 쓰면(44px 원 → 22px) 크기가 바뀔 때마다(48px → 24px) 목록에 없는 새 값이 계속 늘어남
- **기준값 하나에서 파생시키는 구조(방식 2)를 권장.** 각짐/둥긂 취향이 바뀌어도 기준값 한 줄만 고치면 전체가 따라옴. 파생값을 개별로 덮어쓰기 시작하면 이 장점이 사라짐

## 값을 정하는 기준

| 칸 | 어떤 값을 넣나 |
|---|---|
| 기준값 | 먼저 정한다. 여기서 나머지가 파생됨 |
| 버튼·입력창 | 기준값과 같거나 조금 작게. 높이가 작은 요소는 모서리가 크면 알약처럼 보임 |
| 카드 | 버튼과 같거나 크게. **카드가 버튼보다 작으면 어색함** |
| 큰 모달·컨테이너 | 카드보다 크게 |
| 원형 | 999 고정 |

- **면적이 클수록 모서리를 크게.** 같은 값을 큰 면과 작은 면에 함께 쓰면 큰 쪽이 각져 보임
- **값의 종류는 3종 안쪽으로.** 자리마다 다른 값을 주면 규칙이 아니라 나열이 됨
- **중첩 시:** 카드 안에 요소가 들어가면 안쪽 모서리는 바깥보다 작아야 함

## 방향 고르기

| 방향 | 기준값 성격 |
|---|---|
| 또렷함 / 단단함 (업무 도구) | 0 또는 아주 작게 |
| 표준 / 범용 | 중간 |
| 부드러움 / 친근함 (B2C·커머스) | 크게 |
| 알약형 (태그·칩 중심 UI) | 버튼까지 999 — 단, 카드는 따로 정할 것 |

## 체크리스트
- [ ] "원형은 999" 한 줄이 반드시 포함되어 있는가
- [ ] 값의 종류가 3종 이내인가
- [ ] 카드가 버튼보다 같거나 큰가
- [ ] 방식 2를 골랐다면, 파생값을 개별로 덮어쓰지 않았는가
