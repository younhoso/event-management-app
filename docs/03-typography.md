# 03. Typography — 글자 크기 다섯 개

## 채우는 칸

```
## Typography
- Font: [폰트 이름] (fallback: system-ui, sans-serif)
- 화면 제목 [__]px / 굵기 [___]
- 섹션 제목 [__]px / 굵기 [___]
- 카드 제목 [__]px / 굵기 [___]
- 본문 [__]px / 굵기 [___]
- 부가 정보 [__]px / 굵기 [___]
- 굵기는 [___]과 [___]만 쓴다
- 행간은 본문 [___], 제목 [___]
```

## 작성 규칙

- **딱 5단계.** IBM/Shopify/무지시 실험 모두 자리는 5개로 수렴 (화면 제목·섹션 제목·카드 제목·본문·부가 정보). 폰트 시스템 자체는 수십 단계를 정의해도 화면 하나에는 5개만 쓰임
- **굵기는 반드시 2종만.** 보통 본문용 하나 + 제목용 하나. 크기만 정하고 굵기를 안 정하면 AI가 굵기를 섞어 써서 화면이 무거워짐
- 위계 사이가 애매하면 세 번째 굵기를 딱 하나만 예외로 허용하고, 어디에 쓰는지까지 적는다
- **행간도 함께 적는다.** 크기만 정하면 AI가 기본값(1.2 전후)을 써서 본문이 답답해짐

## 값을 정하는 기준 (어떤 폰트를 쓰든 공통)

| 칸 | 어떤 값을 넣나 |
|---|---|
| 본문 | **여기부터 정한다.** 나머지 4개는 본문 기준으로 위아래를 잡는다 |
| 부가 정보 | 본문보다 작게. 너무 작으면 못 읽음 — 모바일에서는 하한선을 지킬 것 |
| 카드 제목 | 본문과 같거나 한 단계 위. 굵기로 구분해도 됨 |
| 섹션 제목 | 카드 제목보다 뚜렷하게 위 |
| 화면 제목 | 가장 큼. 화면당 1개만 등장 |

- **단계 사이는 최소 2px 이상 벌린다.** 1px 차이(12/13px)는 위계로 읽히지 않고 "안 맞는다"는 인상만 남김
- **위로 갈수록 간격을 넓힌다.** 본문→카드 제목은 좁게, 섹션 제목→화면 제목은 넓게 — 일정한 간격으로 올리면 위계가 밋밋해짐
- **행간:** 본문은 넉넉하게(1.5 전후), 제목은 좁게(1.2~1.3). 글자가 클수록 행간 배수는 작아진다

## 방향 고르기

| 방향 | 본문 크기 | 굵기 2종 | 크기 간격 |
|---|---|---|---|
| 정보 밀도 우선 (대시보드·B2B) | 작게 | 굵기 차를 작게 (얇은 쪽 / 중간) | 좁게 |
| 읽기 우선 (콘텐츠·미디어) | 크게 | 굵기 차를 작게 | 좁게, 행간을 넉넉히 |
| 임팩트 우선 (랜딩·브랜드) | 보통 | 굵기 차를 크게 (얇은 쪽 / 아주 굵은 쪽) | 넓게 |
| 모바일 앱 | 보통~작게 | 중간 정도 차이 | 보통 |

## 폰트 고르기

- **한글이 있으면 한글 지원 폰트부터 정한다.** 영문 폰트만 정하면 한글이 fallback으로 떨어져 전혀 다른 인상이 됨
- **fallback을 반드시 적는다.** 로딩 실패 시 기준이 없으면 브라우저 기본 세리프로 떨어지는 경우가 있음
- 본문용 1종이면 충분. 제목용 폰트를 따로 두려면 **왜 필요한지**까지 적을 것

## 체크리스트
- [ ] 정확히 5단계인가 (10종 이상 나오면 흔들린 것 — 위계가 아님)
- [ ] 굵기를 크기와 함께 명시했는가
- [ ] 굵기가 정확히 2종인가 (예외를 뒀다면 사용처까지 적었는가)
- [ ] 단계 사이가 1px 차이로 갈리지 않는가
- [ ] 행간을 본문/제목 각각 적었는가
- [ ] 한글 폰트와 fallback을 적었는가
