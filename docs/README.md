# 디자인 시스템 템플릿 킷 — 사용 안내

프로젝트마다 반복해서 채우는 "AI에게 화면을 만들어달라고 할 때 같이 주는 규칙 파일" 모음입니다.
특정 프로젝트 전용이 아니라, **매번 복사해서 쓰는 범용 템플릿**입니다.

## 파일 구성 — 두 종류로 나뉨

**① 복사해서 쓰는 실물 파일**

| 파일 | 내용 |
|---|---|
| `DESIGN.template.md` | 01~09를 `@docs/...` 경로로 불러오기만 하는 참조 인덱스. 내용은 담지 않음 |
| `DESIGN.shadcn.md` | shadcn/ui 공식 기본값으로 이미 채워진 완성본. `--primary`, `--radius`만 바꿔 바로 사용 |

**② 채우는 칸 + 규칙이 들어있는 본체 파일**

각 파일은 **`## 채우는 칸`(빈칸) → `## 작성 규칙` → `## 값을 정하는 기준` → `## 방향 고르기` → `## 체크리스트`** 순서로 같은 구조입니다.
구체적인 값(색·px·폰트)은 어디에도 박혀 있지 않습니다 — 어떤 브랜드든 그대로 쓸 수 있도록, **"어떤 성격의 값을 넣어야 하는지"만** 적혀 있습니다.

| 파일 | 채우는 것 |
|---|---|
| `01-style-reference.md` | 서비스 이름 + 분위기 단어 3개 + 테마/화면 크기 |
| `02-colors.md` | 색 7개 + 바탕/표면 밝기 관계 |
| `03-typography.md` | 폰트, 글자 크기 5단계, 굵기 2종, 행간 |
| `04-spacing.md` | 간격 스케일 + 자리별 여백 4종 |
| `05-radius.md` | 모서리 — 자리별 지정 또는 기준값 파생 |
| `06-elevation.md` | 깊이 — 그림자 / 배경색 차이 / 테두리 중 하나 |
| `07-components.md` | 앞의 값을 실제 컴포넌트 5종에 연결 |
| `08-guidelines.md` | DO / DON'T — 가장 중요한 파일, 증상별 원인 체크표 포함 |
| `09-shadcn-tokens.md` | 위 값을 CSS 변수로 옮기는 칸 (shadcn/ui 변수 이름 규약) |

`DESIGN.template.md`는 01~09 경로만 나열한 인덱스입니다. 값은 **각 번호 파일 안에서 직접 채웁니다.**

## 새 프로젝트 시작 체크리스트

1. `docs/` 폴더를 프로젝트에 복사하고, `DESIGN.template.md`를 `DESIGN.md`로 복사
2. `01`부터 **한 파일씩** 채운다 — 전부 한 번에 채우지 않기. 각 파일의 "값을 정하는 기준" 표를 보면서 브랜드에 맞는 값을 직접 넣는다
3. 화면 1~2장을 뽑아보고, 마음에 안 드는 부분을 `08-guidelines.md`의 DON'T에 즉시 추가
4. 코드로 옮길 때 `09`의 CSS 변수 칸을 채운다 (02~07 값을 그대로 옮기고, 여기서 새 값을 만들지 않는다)
5. 화면을 만들 때마다 **매번 같이** AI에게 전달 (세션이 바뀌면 AI는 이전 파일을 기억 못 함)

## 값이 안 정해질 때

빈칸 앞에서 막히면 두 가지 방법이 있습니다.

- **`DESIGN.shadcn.md`를 본다** — shadcn/ui 기본값으로 전부 채워진 완성본. 여기 있는 값이 "채워진 상태가 어떤 모습인지"의 예시가 됩니다
- **01번의 분위기 단어로 돌아간다** — 01번 맨 아래 표가 세 단어에서 02~06의 값 방향을 역으로 끌어내 줍니다

## 툴별 적용 위치

- **Figma Make**: Code → guidelines 폴더 → 파일 1개만 (여러 개 넣으면 충돌)
- **Lovable**: Project settings → Knowledge (10,000자 제한, 템플릿 완성본은 약 3천자 내외)
- **Claude / Cursor 등**: 프롬프트 최상단에 파일 내용 그대로 붙여넣기
- 첫 화면을 만들기 **전에** 넣을 것. 화면을 먼저 뽑고 나중에 넣으면 앞뒤가 안 맞음

## 핵심 원칙 (모든 파일 공통)

- **목록보다 금지가 잘 먹힌다.** "이 값만 쓴다"보다 "이 값 아니면 쓰지 않는다"가 훨씬 잘 지켜짐
- **개수를 지킨다.** 색 7개, 글자 크기 5종, 굵기 2종 — 실제 제품 디자인 시스템(IBM Carbon, Shopify Polaris) 및 무지시 실험 결과 공통적으로 수렴한 개수
- **"쓴다"만큼 "안 쓴다"도 명시한다.** 그림자를 안 쓰기로 했으면 "그림자를 쓰지 않는다"라고 적어야 함. 빈칸으로 두면 AI는 기본값(그림자 있음)을 씀
- **완벽하게 채우고 시작하지 않는다.** 3줄만 적고 시작 → 걸리는 부분이 생길 때마다 한 줄씩 추가하는 방식이 더 잘 작동함
