# 04. Spacing — 간격

## 채우는 칸

```
## Spacing
- 간격은 [__·__·__·__·__·__]만 쓴다. 그 사이 값은 쓰지 않는다
- 화면 좌우 여백 [__]px
- 카드 안쪽 여백 [__]px
- 카드와 카드 사이 [__]px
- 요소 안쪽의 작은 간격(라벨-입력창 등) [__]px
```

## 작성 규칙

- **기준 단위를 하나 정하고 그 배수만 쓴다.** 4의 배수가 가장 널리 쓰이고(Tailwind·Material·대부분의 디자인 시스템), 8의 배수는 더 성글지만 더 강하게 강제됨. 어느 쪽이든 **하나만** 고른다
- 무지시 실험에서 2, 3, 6, 10, 14, 18, 26px처럼 배수가 아닌 값이 14가지나 섞여 나옴. 10px과 12px처럼 2px 차이는 눈으로 정확히 못 읽고 "뭔가 안 맞다"는 인상만 남김
- **목록만 적지 말고 금지 문장을 꼭 붙인다.**
  - 약한 버전: "간격은 [목록]만 쓴다"
  - 강한 버전 (권장): "간격은 [목록]만 쓴다. 그 사이 값은 쓰지 않는다"
- 아주 미세한 조정이 필요하면(예: 아이콘 정렬) 1~2px 예외 하나는 별도로 명시 가능 — 전체 규칙을 흔들지 않는 선에서
- **스케일은 6단계 안쪽으로.** 값이 많을수록 안 지켜진다

## 값을 정하는 기준

| 칸 | 어떤 값을 넣나 |
|---|---|
| 스케일 | 기준 단위의 배수로, 작은 쪽은 촘촘하게 큰 쪽은 성글게 (예: 1배·2배·3배·4배·6배·8배) |
| 화면 좌우 여백 | 화면 폭이 좁을수록 작게. 이 값이 화면 전체의 "숨 쉬는 정도"를 결정 |
| 카드 안쪽 여백 | 화면 좌우 여백과 **같거나 작게**. 더 크면 카드가 화면보다 넉넉해 보여 어색함 |
| 카드와 카드 사이 | 카드 안쪽 여백보다 **작게**. 같거나 크면 카드가 하나씩 떨어져 보여 목록으로 안 읽힘 |
| 요소 안쪽 작은 간격 | 스케일에서 가장 작은 값. 라벨-입력창, 아이콘-글자처럼 한 덩어리로 읽혀야 하는 짝에만 |

**핵심 규칙 — 가까운 것은 붙이고 먼 것은 띄운다.** 관련된 요소 사이 간격이 관련 없는 요소 사이 간격보다 커지면, 값이 아무리 정확해도 묶임이 잘못 읽힌다.

## 방향 고르기

| 방향 | 화면 좌우 여백 | 카드 안쪽 | 카드 사이 |
|---|---|---|---|
| 밀도 우선 (대시보드·B2B) | 보통 | 작게 | 아주 작게 |
| 모바일 앱 표준 | 작게 | 좌우 여백과 동일하게 | 작게 |
| 여백 여유형 (랜딩·브랜드) | 크게 | 크게 | 보통 |

## 체크리스트
- [ ] 기준 단위(4 또는 8의 배수)를 하나로 정했는가
- [ ] "그 사이 값은 쓰지 않는다" 금지 문장이 포함되어 있는가
- [ ] 자리별(좌우 여백/카드 안쪽/카드 사이) 값을 개별 지정했는가
- [ ] 카드 사이 < 카드 안쪽 ≤ 화면 좌우 여백 순서가 지켜졌는가
- [ ] 스케일이 6단계 안쪽인가
